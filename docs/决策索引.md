# 决策索引

> **这份文档解决一个问题：对话会丢，仓库不会。**
>
> 需求讨论、取舍过程、踩过的坑，原本只存在于对话里。对话被压缩或换人接手之后，
> 那些"为什么这么做"就消失了——后来的人只能看到代码，看不到取舍，于是很容易把
> 已经否决过的方案重新做一遍。
>
> 这份索引把每个决策的**理由、代价、落地位置、验证方式**固定下来，全部来自
> git 提交信息与两份文档（`需求文档.md`、`运行与配置文档.md`），不依赖任何人的记忆。

## 怎么用

| 你想做的事 | 看哪里 |
| --- | --- |
| 想改某个功能，先确认"当初为什么这样" | 按**主题**找到那一行，看「为什么」与「落地位置」 |
| 想确认某条约束还在不在 | 看「验证方式」，直接跑对应测试；测试是**可执行的口径** |
| 接手这个项目 | 从「测试与 CI」和「数据与密钥安全」两节读起，它们决定改动边界 |
| 发现某个决策过时了 | 改代码的同时改这一行；**不要只改代码**——理由失传比代码过时更贵 |

## 怎么重新生成

索引来自 git 历史，所以随时可以重建或核对：

```powershell
# 全部提交标题（按时间正序）
git log --reverse --format='%h %ad %s' --date=short

# 某条决策的完整理由（提交信息里写了理由、代价、否决过的方案）
git show -s --format='%h%n%B' <hash>

# 某条决策改了哪些文件
git show --stat <hash>
```

**维护约定**：提交信息里写清「为什么」和「代价」，这一行才能被提炼出来。
提交信息写得含糊，几个月后没人能重建理由。

| 决策 | 为什么（理由或代价） | 落地位置 | 验证方式 |

| Host 白名单防 DNS rebinding，静态资源也校验 | 域名可解析到 127.0.0.1 且 Origin 看似同源，同源校验形同虚设 | server/lib/security.js | Host 白名单与域名登记用例 |

| 失败登录限速返回 429，并修掉令牌误套静态资源等三个错 | 只改文案状态码仍 401 等于告诉客户端继续试；令牌误套静态资源会让登录页加载不出来 | server/lib/security.js | 失败限速与 429 用例 |
| 安全头齐全且 CSP 不含 unsafe-inline，防闪烁脚本外置 | HSTS 只在真走 HTTPS 时发，否则会把用户困在打不开的地址上 | server/lib/http.js、web/theme-boot.js | 安全头与 CSP 用例 |
| HTTPS 支持自有与自签证书，拿不到证书就启动失败 | 以为走 HTTPS 实际明文传令牌，比启动不起来严重得多 | server/lib/tls.js | HTTPS 端到端真 TLS 用例 |
| 自签证书：序列号重摇到首字节非零（避免 DER 冗余前导零） | `serial[0] &= 0x7f` 保证为正，但有 1/128 概率把首字节变成 0x00，而 DER 的 INTEGER 要求最短编码——那个 0x00 就是非法的冗余前导零，OpenSSL 3.x 直接拒收整张证书（CI 实测 `ERR_OSSL_ASN1_ILLEGAL_PADDING`，约 1/150 的偶发红；本机压测 300 次失败 2 次、强制首字节 0x00 几乎必现、0x01 则 5/5 通过） | server/lib/x509.js、test/lib/self-signed-cert.js | test/calendar-selftest.js 里确定性回归（把第一次摇到的首字节改成 0x00，必须重摇且证书被 OpenSSL 接受） |
| 自签证书：PEM 正文每行 64 字符，且**整除 64 时不留空行** | `replace(/(.{64})/g,'$1\n')` 会在 base64 长度正好是 64 整数倍时于末尾多留一个换行，模板里紧接着的 `\n` 就让 BEGIN/END 之间多出一个空行；OpenSSL 读到空行即停、DER 被截断，整张证书被拒收。长度由**允许的域名/IP 列表**决定，约 1/16 的配置会撞上（本机实测 DER 767 字节 → base64 1024 = 16×64 时报 `SSL_CTX_use_certificate_chain` / `ERR_OSSL_ASN1_WRONG_TAG`，改一个字母立刻就好） | server/lib/x509.js、test/lib/self-signed-cert.js | 同一回归用例里钉住"base64 正文长度整除 64"这一档，并断言 PEM 中不出现空行、证书能被 `X509Certificate` 解析 |
| saveSecurity 补上搬进来的端口与访问令牌 | 漏提交比报错更难发现，改了不保存 | web/views/settings.js | 无 |

## 教训清单（比决策更容易失传）

这些不是功能选择，而是**踩过的坑**。它们最容易在换人/换会话后重犯，所以单独列出。

| 教训 | 症状 | 正确做法 |
| --- | --- | --- |
| 字符串替换会**静默失败** | 按 `maxChars` 去替换真实签名 `maxChars = 40_000`，没匹配上 → 参数没加上 → `withHtml` 成为未定义变量 → `ReferenceError` 被外层 catch 吞掉 → 表现为"莫名其妙的功能 bug"，查了很久 | 替换后**回读确认**；`catch` 里吞异常必须留日志，否则会把工具错误伪装成逻辑缺陷 |
| CSS 级联按**顺序**决胜，同优先级时后写的赢 | 状态色 `.tag-warn` 写在基础规则 `.tag` 之前，被后者整体覆盖 → 状态标签**从未**有过颜色，而没人发现 | 状态类写成双类名（`.tag.tag-warn`）提高特异性，不依赖书写顺序 |
| 新增同名函数会**顶掉**页面原有的 | 给设置页加的下拉助手也叫 `selectInput`，把原有的同名函数覆盖 → 旧调用把字符串当数组传 → 整页 `options.map is not a function` | 加助手前先在本文件搜同名；不确定就取一个更具体的名字 |
| 测试里 `listen(0)` 后**立刻**读端口 | Windows 上偶发 `address()` 为 `null` 或 `{port:0}` → 拼出 `http://127.0.0.1:0` → 下游只报一句 `bad port`，看不出哪一步错 | 等待并校验端口（`test/lib/port.js`）；错误信息要自带上下文，不要只报底层错误 |
| **断言写宽了会假报错** | 正则 `src="https://…"` 命中了 `data-blocked-src="https://…"` 的子串；把密钥掩码 `***` 当成残留的 Markdown 粗体 | 能用 DOM 精确检查就别用正则；断言要区分"真内容"与"标记" |
| **把降级当成结论** | 分类调用失败会降级成空标签，与"模型认为这封邮件不属于任何项目"混在一起 → 用户读到"模型没有建议"，其实是**一次都没调通** | 区分"没有结果"与"调用失败"；用户主动花钱的动作不降级，失败就如实报错 |
| **面向使用者的文档要等能用再写** | 视图还没接线就把功能写进 README/运维文档 → 变成"文档说能做、实际做不到" | 需求文档可以先写（它定义目标），README 与运维文档等功能真的可用再写 |
| 运行中的**旧进程**会让新代码看起来失效 | 前端页面从磁盘读所以刷新即更新，服务端路由是启动时加载 → 报"接口不存在"，而代码里明明有 | 见到"接口不存在/字段没生效"先怀疑旧进程：重启服务并强制刷新 |
